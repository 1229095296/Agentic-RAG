# 05｜测试、排障与企业化路线

## 1. 分层运行测试

在 `enterprise-demo` 安装依赖后运行：

```bash
.venv/bin/python -m pytest -q
.venv/bin/python smoke_server.py
```

第一条运行 6 个测试函数，第二条在随机回环端口启动真实服务，请求后自动关闭。测试使用临时数据库，不修改真实 `data/`。

原项目的纯逻辑测试：

```bash
cd ../stateflow-musique-release
../enterprise-demo/.venv/bin/python -m pytest -q -p no:cacheprovider
```

这可以运行 22 个状态、奖励、池测试。缺少 Slime 时 `tests/conftest.py` 提供替身，仅支持逻辑测试，不会启动模型服务，也不能证明真实 Slime API 版本兼容。

## 3. 常见问题

### 双击启动提示环境未安装

Git 不会上传 `.venv`。先依照使用教程创建虚拟环境和安装依赖。已有安装只对该项目目录有效，不会自动共享给重新克隆的仓库。

### macOS 不允许执行 command

右键选择“打开”。若缺执行权限，在项目目录运行 `chmod +x 启动演示.command`。不要因此关闭整机安全机制。

### 浏览器打不开 / 8765 被占用

查看启动窗口是否仍运行。首次加载可能超过两秒，手工刷新。若端口已占用，关闭旧演示窗口；不要随意杀死未知进程。服务只监听本机，其他机器不能直接访问。

### Qdrant 提示目录被占用

不要启动多个实例或使用多个 Uvicorn worker 共享本地目录。先停止旧服务。不同实例应使用不同 KNOWLEDGE_DATA_DIR，或者将来迁移到 Qdrant 服务端模式。

### 文档入库失败

检查扩展名、10 MB 限额、编码、文件是否损坏、PDF 是否加密或扫描件。文件名后缀只是路由，不是文件内容安全认证。生产需要病毒检测、隔离解析、解压限制与超时。

### 同名文件被替换

当前 doc_id 来自文件名摘要，不来自原始目录。不同目录同名上传会视为同一文档；这是原型限制。接入 Wiki 等来源时用源系统稳定 ID。

### 命中结果却没有回答，或摘录不够相关

当前无策略模型；每个 Chunk 只选第一条可用原文，不做精确证据排序。字符 n-gram 只能衡量词面重合，少量共字也可能召回。不能把结果当成可靠综合答案。

### Gate 通过但没有 citations

空证据、未解问题非空、decision=search 是合法状态。Gate 不负责保证召回或回答充分；看 citations、trace 和 mode，而不是只看 gate.ok。

### 入库很慢

每次入库和启动全量重建 Qdrant 与 TF-IDF；适合小量样例，不适合企业全量资料。暂未提供后台任务、增量写入或进度接口。不要以本原型速度作为向量库本身性能结论。

### 原模型调用不到检索

检查 MUSIQUE_SEARCH_URL、服务状态和网络位置。容器内 127.0.0.1 不是宿主机。先使用 curl 验证，再排查模型动作协议。不要把本地无认证服务直接公开。

### 依赖安装不成功

确认 Python 3.12 及 wheel 平台一致。锁定清单固定版本，不保证其他 Python 版本均有 wheel。通过可信包源下载，不要在聊天或代码里填凭据。

## 4. 发布前安全清单

- 排除 `.venv`、`.download-env`、offline_packages、缓存、模型、数据集。
- 排除 data、state_pool、traces、SQLite、向量数据及用户原文。
- 排除 `.env`、访问令牌、私钥和含凭据 URL；仅提交不含秘密的配置示例。
- 不把测试替身说成真实模型训练验证。
- 保留原代码来源，不给未声明许可证的代码擅自添加授权。
- Git 历史中的秘密不能靠 `.gitignore` 消除；如果发现已提交凭据，应先撤销并单独治理历史。

本次仅对当前仓库源文件做模式扫描，不构成完整安全审计或依赖供应链保证。

## 5. 变为真正企业 Agentic RAG 的顺序

### 第一阶段：检索质量

换用合适的本地/企业语义 Embedding，同步索引端与查询端；构建 BM25/语义融合、重排、拒答阈值和标准问题集；改进文档结构、表格与 OCR。改模型或切块逻辑时版本化并重建。

### 第二阶段：真正 Agent 策略

新增 PolicyProvider，统一 search/evidence_state/answer 输出；将线性图改为有预算、错误路由与循环的图；模型写状态，规则只验证不悄悄修复。增加 AnswerVerifier，区分缺失、矛盾与支持。

### 第三阶段：权限和数据生命周期

接企业身份；用服务端可信用户上下文在召回前过滤；文档修改/删除/权限变更使索引、缓存、引用、检查点失效。训练池与线上数据分开，日志脱敏与保留策略明确。

### 第四阶段：运维与评测

独立检索服务和事务存储；任务队列、重试、检查点、审计、备份、指标与容量测试。不要依赖单进程 RLock 或重建全部集合。

### 第五阶段：策略训练

先修复原回放成功率、预算、路由、版本过滤和 eval 隔离；比较静态 RAG、普通 Agentic RAG、证据 Gate、full-only GRPO、固定 replay、自适应 replay。固定模型、语料与资源预算，衡量准确率、引用支持、成本及失败率。
