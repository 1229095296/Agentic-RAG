# 02｜代码结构与实现导读

## 1. 两套代码，两个入口

| 目录 | 入口 | 核心任务 | 外部前提 |
|---|---|---|---|
| `enterprise-demo` | `launcher.py` → `app.py` | 本地文件入库、索引、检索、证据校验 | 安装 Python 依赖 |
| `stateflow-musique-release` | Slime 调用 `generate_stateflow_direct.generate` 等钩子 | 模型多轮检索 rollout、奖励、回放采样 | 模型服务、Slime、数据集、检索服务 |

不是两个独立的完整 Agent 框架，也没有一个顶层命令把它们自动全部部署。

## 2. 推荐源码阅读顺序

1. `enterprise-demo/app.py`：了解系统提供什么接口。
2. `knowledge.py`：了解文本从文件到检索结果的全过程。
3. `runtime.py`：了解检索结果如何变成证据状态。
4. `stateflow_gate.py`：理解确定性校验边界。
5. `test_demo.py`：用断言反向理解设计契约。
6. 原项目的 `generate_stateflow_direct.py`：对比真正模型动作循环。
7. 原项目的奖励、池、数据源和采集模块：理解训练闭环。

## 3. 本地演示逐文件导读

### 3.1 launcher.py：前台生命周期

`main()` 先探测 8765 端口，再用 Uvicorn 前台启动 `app`，并安排浏览器打开本地地址。端口探测不等于锁定端口，探测后仍可能被其他进程抢占；发生冲突请停止旧实例。

它不安装依赖、不导入用户文件、不调用模型、不托管后台守护进程。`启动演示.command` 只是检查环境并运行它。

### 3.2 app.py：HTTP 边界

`lifespan()` 创建一个 `KnowledgeBase` 和一个 `OfflineRuntime`；结束时关闭 SQLite/Qdrant。默认数据目录相对 app.py，不受当前终端目录影响。

- `home()` 返回本地 `index.html`。
- `health()` 声明离线模式和模型未配置状态。
- `ingest()` 限量读取上传内容，把解析交给线程池；格式错误返回 400。
- `demo()` 导入仓库内虚构示例。
- `retrieve()` 将内部结果适配成原 StateFlow 要求的 `result` 列表。
- `ask()` 执行图，不调用生成模型。

这里的请求校验只管输入形状与大小，不是用户认证。上传解析器也不是隔离沙箱；不要把仅限本地的服务直接公开。

### 3.3 knowledge.py：知识库的主体

#### parse_file(name, content)

输出 `(location, text)` 列表：

- TXT/MD：UTF-8 解码，location 为“正文”。Markdown 不做 AST 结构化解析。
- PDF：逐页提取文本，location 保存页码；加密或无文本 PDF 拒绝。
- DOCX：按文档阅读顺序提取段落／表格；表格单元格用竖线拼接。

先分 section 再分 Chunk，因此不会跨 PDF 页或 Word 段落合并；长文档里很多短段落可能产生较多小块。

#### KnowledgeBase.__init__()

建立 SQLite 的 documents/chunks 两张表；配置 LlamaIndex SentenceSplitter；创建字符 HashingVectorizer；打开本地 Qdrant；执行 `_rebuild()`。

`tokenizer=list` 表示这里的 500/70 是按字符计量的分片目标，不是某个大模型的 token 数。重叠只在同一 section 内的分片之间起作用。

#### ingest(name, content)

1. 去除上传文件名的目录部分。
2. 解析文件。
3. 用文件名摘要构建 doc_id，用原始字节和管线版本构建 version。
4. 各 section 经 SentenceSplitter 形成 Chunk。
5. Chunk 内按中英文标点和换行切 Span。
6. 构建 doc/version/section/index 组成的 chunk_id 与 span_id。
7. 加锁检查当前版本；同版本直接返回 unchanged。
8. 用 SQLite 事务删除同文档旧 Chunk、插入新记录、更新目录。
9. 依据 SQLite 重建向量集合和 TF-IDF。

代价：每次导入都全量重建，不是增量索引。SQLite 提交与 Qdrant 更新不是跨存储原子事务；若重建中断，可重启从 SQLite 恢复，但当前进程可能暂时不可用。

#### _rebuild()

SQLite 是事实来源，Qdrant 为派生索引。删除旧 chunks 集合后重建 2048 维 cosine 索引，分批上传字符 hashing 向量；同时对全文构建字符 TF-IDF 矩阵。

这套策略方便小样本恢复，不适合大型生产知识库。启动时也会重建；持久化 Qdrant 不意味着当前实现启动时直接复用已有集合。

#### search(query, topk)

1. 查询经同一 HashingVectorizer 变为 2048 维向量。
2. 从 Qdrant 获取相似候选，记录排名。
3. 全部 Chunk 用 TF-IDF 计算查询相似度，记录正相似项排名。
4. 两路用 `Σ 1/(60+rank)` 做 RRF 融合。
5. 仅保留 TF-IDF 相似度大于零的条目，按融合分返回 topk。

因此并不是“只取 Qdrant 候选再重排”：TF-IDF 正相似的其他条目也能进入输出。两路都基于字符特征，不能叫语义+关键词混合，也没有 cross-encoder reranker。RRF 分数不是置信度概率。

#### documents() / close()

前者读取目录，后者释放数据库资源。`RLock` 负责进程内并发；不是分布式锁，禁止多 worker 共享同一个本地 Qdrant 目录。

### 3.4 runtime.py：状态图与保守输出

`RunState` 描述 question、hits、evidence_state、gate、answer、citations、trace、mode。

`OfflineRuntime` 编译的图为：

```text
START → retrieve → build_evidence → gate → extract → END
```

- `retrieve()`：直接用用户问题查询，默认取 3 个 Chunk。
- `build_evidence()`：每个 Chunk 找第一个长度 ≤600 的完整 span，最多取 3 条。没有模型做相关性选择。
- `gate()`：把状态包装成 evidence_state 标签，调用原验证函数。
- `extract()`：Gate 通过才从选中状态创建 citations，返回固定提示和原文。
- `ask()`：调用 graph.invoke，移除庞大的 hits 后返回。

始终保留未解问题和 search 决策，因为词面命中不能证明能回答。图没有按照 decision 路由，这是有意限制的离线演示，不是已经实现的多轮 Agent。

还有一个重要边界：无结果时空 evidence + 非空 open_questions + search 可以通过 schema Gate。故“Gate 通过”不能用作检索成功率指标。

### 3.5 stateflow_gate.py：严格但有限

从原项目 `direct_evidence_state.py` 原样复制。关键类型为 EvidenceItem、DirectEvidenceState、StateValidation。

`parse_and_validate_state()` 的顺序：长度 → 单标签 → JSON → 顶层键 → 条目数量与类型 → span 可见性 → 原文连续摘录 → 本轮证据要求 → 未解问题 → 决策一致性。

默认上限：6 条证据、4 个未解问题、5000 字符状态；未解问题单条 ≤200 字符。完整 span 可直接匹配；子串还受长度与词数限制，中文子串可能被不合理拒绝。

它不会验证事实、推理链、权限或最终答案支持。`state_from_anchor()` 是旧池 schema 到 direct schema 的适配，不在当前离线图中使用。

### 3.6 index.html：操作与显示

浏览器使用 fetch 调用本地接口。通过 textContent 展示用户文档和返回内容，避免把文档原文当 HTML 插入。未引入第三方 CDN、前端框架或登录。

上传/检索失败显示提示；不是完整的企业管理后台。文件删除、全文预览、导出、权限管理都没有实现。

### 3.7 测试和辅助文件

- `test_demo.py`：逻辑、持久化、版本、分片、解析、Gate、API。
- `smoke_server.py`：真正绑定回环端口，测试后关闭，临时数据自动清理。
- `sentence_utils.py`：原英文句子切分参考副本，**实际离线入库没有调用**。
- `sample.md`：虚构样例。
- `requirements.txt`：允许版本区间。
- `requirements.lock.txt`：本次安装的具体版本。
- `AGENTS.md`：后续维护说明，不是运行时代码。

## 4. 原 StateFlow 目录逐模块定位

| 文件 | 对应实现功能 |
|---|---|
| generate_stateflow_direct.py | 实际主 rollout；动作解析、检索调用、严格阶段控制、Gate、训练 token 与 loss mask、reward 入口 |
| direct_evidence_state.py | 完整模型状态 schema 和 Gate；不自动修复模型输出 |
| evidence_state.py | E/U/H/B 池状态、序列化、防标记泄漏；另有当前 direct 不调用的旧 Canonicalizer |
| stateflow_data_source.py | 从完整问题／中间状态采样，fan-out 为独立 GRPO 组 |
| state_pool.py | JSONL 成功状态池、去重、回放锚点和 EMA 难度反馈 |
| harvest_states.py | 完整轨迹筛选、状态采集、后缀成功率反馈 |
| musique_reward.py | 答案 EM/F1、格式、效率与可选证据评分工具 |
| generate_musique.py | 无 evidence_state 的 Search-R1 式基线 |
| musique_to_slime.py | 数据转换；须检查输入字段是否与自己的数据一致 |
| prompt_utils.py | 提取问题文本和标识 |
| sentence_utils.py | 英文为主的确定性句子切分 fallback |
| tests/ | 状态、池、奖励回归；Slime 替身不验证真实模型服务 |
| configs/stateflow.env.example | 运行参数示例，不是模型或训练部署脚本 |

## 5. 功能需求 → 应修改哪一处

| 需求 | 入口 | 连带要求 |
|---|---|---|
| 增加解析格式/OCR | parse_file | 来源定位、失败路径、解析安全与样本测试 |
| 改 Chunk 大小 | KnowledgeBase.__init__ | 更新 PIPELINE_VERSION，重新入库，验证召回 |
| 改语义 Embedding | _rebuild + search | query/index 同模型、维度、版本迁移，不能只换查询端 |
| 加重排器 | search 输出前 | 不把模型概率直接当事实支持 |
| 加策略模型 | runtime + 新适配器 | 动作 schema、循环边、预算、错误恢复、模型输出 Gate |
| 企业权限 | 接入/元数据/检索入口 | 服务端用户身份，过滤后才把文本送模型 |
| 支持删除 | SQLite + Qdrant + API | 版本、缓存、日志和检查点一起失效 |
| 训练回放修复 | 原 harvest/data_source/pool/generate | 见训练融合教程，避免改动时破坏组边界 |
