# 01｜使用与演示教程

## 1. 你将得到什么

读完并操作后，你能：启动本地页面；导入文件；查看分片数量；检索并追溯证据；更新同名文件；通过接口使用检索服务；运行测试。

不需要 GitHub 令牌、模型 API Key、Docker、GPU 或模型权重。安装 Python 包时需要网络，离线安装方法见下文。

本教程演示的是 **入库 → 检索 → 证据校验**，不演示模型自由生成答案。页面出现“尚未经模型判断”是设计行为，不是报错。

## 2. 准备环境

推荐 Python 3.12 与独立虚拟环境。当前验证平台为 Apple Silicon macOS。其他平台不应视为已经实测。

### macOS / Linux

```bash
git clone https://github.com/1229095296/Agentic-RAG.git
cd Agentic-RAG/enterprise-demo
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
.venv/bin/python launcher.py
```

### Windows PowerShell

```powershell
git clone https://github.com/1229095296/Agentic-RAG.git
cd Agentic-RAG/enterprise-demo
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.venv\Scripts\python.exe launcher.py
```

`requirements.lock.txt` 固定本次实际安装版本，但不含跨平台 wheel 哈希，不等同于所有平台完全相同的可复现构建。需要重新选版时可使用 `requirements.txt` 的版本范围，之后必须重新测试。

### 离线安装

在与目标系统、CPU 架构和 Python 版本匹配的联网机器上运行：

```bash
python3.12 -m pip download --only-binary=:all: -r requirements.lock.txt -d offline_packages
```

把下载目录复制到目标机器的 `enterprise-demo`，创建虚拟环境后：

```bash
.venv/bin/python -m pip install --no-index --find-links offline_packages -r requirements.lock.txt
```

macOS 也提供「下载依赖.command」下载助手；它按 `requirements.txt` 的范围下载，版本可能与锁定版本不同。需要严格复现时优先使用上面的锁定清单命令。离线包、环境文件不要上传 Git。

## 3. 启动与关闭

运行 `launcher.py` 或 macOS 双击「启动演示.command」。页面地址固定为：

http://127.0.0.1:8765

启动窗口必须保留。启动器两秒后尝试打开浏览器；首次加载较慢时手工刷新页面。关闭窗口或按 Control+C 停止。

不要同时运行两个实例。默认数据路径为 `enterprise-demo/data/`；此目录首次启动自动创建。退出后再次启动数据仍在，但向量集合会根据目录数据库重建。

若想隔离演示数据，可在启动前设置 `KNOWLEDGE_DATA_DIR` 为另一个目录；这不是多租户权限机制。

## 4. 十分钟讲解脚本

### 步骤 A：导入示例

点击「导入示例制度」。预期：左侧出现“示例差旅制度.md”及片段数量。

讲解：原始文本已经经过解析、Chunk 切分、版本化和索引；不是只把文件路径传给模型。示例是虚构制度，不代表真实企业规定。

### 步骤 B：查询并查看证据

输入“差旅报销需要什么材料？”并点击「查找相关原文」。

预期：出现原文摘录、文件名、位置、版本和 span_id；证据校验通过。展开「证据状态与执行记录」，能看到四个节点：retrieve、build_evidence、gate、extract。

**摘录可能只是命中文档中的首个可选句子，不保证正好包含完整报销材料。** 当前规则每个命中 Chunk 只选第一个长度不超过 600 的 span，而非做模型相关性选择；这也是后续替换证据选择策略的主要切入点。

### 步骤 C：解释为什么没有完整答案

状态保持 `decision=search`，且保留“尚需模型或人工判断”的未解问题。当前图没有循环边，因此仍会结束并返回摘录。

这并非宣称“需要搜索就一定继续搜索”；它明确区分演示状态协议与真正模型策略。Gate 通过只表示字段及摘录来源合规。

### 步骤 D：上传自己的文档

选择 PDF、DOCX、MD、TXT，点击「导入文件」。单文件上限 10 MB。

- 文本需 UTF-8；UTF-8 BOM 可以处理。
- PDF 必须有可提取文字，不能是纯扫描图片或加密文件。
- Word 只支持 DOCX，不支持旧 DOC。
- 表格会以单元格文本拼接，不保证复杂布局和跨块表头。

上传后检索文档中特有词语。词面相近更容易命中；不要期待同义改写或跨语言语义检索。

### 步骤 E：验证重复导入与更新

同一个文件再次上传，预期提示“未变化，无需重复入库”。修改内容但保持文件名不变后上传，旧版本 Chunk 会被替换。

重要：本原型按文件名决定文档身份。两个不同目录的同名文件会互相替换；重命名则视为新文档。企业连接器必须改用源系统稳定文档 ID。

### 步骤 F：查询不存在的知识

输入与材料完全无关的词。若没有字符特征交集，会返回未找到相关原文。若共享少量字符，仍可能命中无关内容，因为没有校准的相关性阈值；不能把“检索有结果”当成有答案。

## 5. 开发者接口体验

服务启动后访问 http://127.0.0.1:8765/docs ，这是 FastAPI 的接口测试页。本地 Swagger 页面可能依赖外部静态资源；断网时直接使用命令行请求。

```bash
curl http://127.0.0.1:8765/health
curl -X POST http://127.0.0.1:8765/demo
curl -X POST http://127.0.0.1:8765/retrieve \
  -H 'Content-Type: application/json' \
  -d '{"queries":["差旅报销"],"topk":3,"return_scores":true}'
curl -X POST http://127.0.0.1:8765/ask \
  -H 'Content-Type: application/json' \
  -d '{"question":"差旅报销需要什么材料？"}'
```

`/retrieve` 返回给程序用的检索文档；`/ask` 还会执行状态图与 Gate，两者不等价。
