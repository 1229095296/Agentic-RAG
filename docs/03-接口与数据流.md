# 03｜接口与数据流

## 1. 接口一览

| 方法 | 路径 | 输入 | 返回 |
|---|---|---|---|
| GET | `/` | 无 | 本地页面 |
| GET | `/health` | 无 | status、mode、llm_configured、documents |
| GET | `/documents` | 无 | 文档目录数组 |
| POST | `/ingest` | multipart 字段 file | name、chunks、unchanged；新版本含 version |
| POST | `/demo` | 无 | 虚构示例的入库结果 |
| POST | `/retrieve` | queries、topk、return_scores | 与原项目契约匹配的嵌套 result |
| POST | `/ask` | question | 状态图结果、摘录、引用与 trace |

仅绑定 localhost，无认证，无跨租户隔离，不得转发为企业公共服务。

## 2. 上传与版本数据流

```text
UploadFile
  → 限量读取字节（≤10 MB）
  → parse_file → [(location,text)]
  → SentenceSplitter → chunks
  → 中文/英文句子边界 → spans
  → SQLite 提交目录与块
  → Qdrant/TF-IDF 重建
```

### 标识构成

- `doc_id`：清理后的文件名 SHA-256 摘要前 24 位。
- `version`：文件字节 + PIPELINE_VERSION 的 SHA-256 前 24 位。
- `chunk_id`：doc_id、version、section 序号、chunk 序号。
- `span_id`：chunk_id + `:sN`。
- Qdrant point id：根据 chunk_id 生成 UUID5。

这些标识在相同文件名、相同字节与相同管线下可重复；变更文档或管线版本会变化。它们不是数字签名，也不能证明访问授权或来源未被恶意篡改。

### SQLite 两张表

| 表 | 字段 | 用途 |
|---|---|---|
| documents | doc_id / name / version / chunk_count | 当前文档目录 |
| chunks | chunk_id / doc_id / name / version / location / text / spans | 当前版本原文块与证据 |

旧版本不保留；没有历史版本查询。spans 为 JSON 文本。没有 foreign key 约束，跨表一致性依赖入库事务。

## 3. `/retrieve` 契约

请求：

```json
{"queries":["差旅报销"],"topk":3,"return_scores":true}
```

响应形状示意（ID 为占位，不是实测固定值）：

```json
{
  "result": [[{
    "document": {
      "doc_id": "<chunk_id>",
      "parent_document_id": "<document_id>",
      "title": "示例差旅制度.md",
      "file_name": "示例差旅制度.md",
      "contents": "<chunk 原文>",
      "text": "<同一 chunk 原文>",
      "spans": [{"span_id":"<chunk_id>:s1","text":"<句子原文>"}],
      "version": "<文档与管线版本>",
      "location": "正文"
    },
    "score": 0.032
  }]]
}
```

`result[i]` 对应 `queries[i]`。无结果为该位置的空数组。这里对外 `document.doc_id` 特意使用 chunk_id，使不同检索块具有独立可引用来源；父文档身份另存 parent_document_id。

分数是排名融合分，不是正确率。只在 return_scores=true 时输出。原 StateFlow 请求为 false，不依赖此分数。

输入约束：queries 数量 1–8；每条非空且不超过 2000 字符；topk 在 1–10。部分约束由 Pydantic 返回 422，查询内容约束返回 400。

## 4. `/ask` 与证据状态

请求：

```json
{"question":"差旅报销需要什么材料？"}
```

关键结果字段：

- question：原始问题。
- mode：`offline_extract_only`。
- evidence_state：三字段协议。
- gate：ok、code、message。
- answer：固定说明文字，不是模型综合答案。
- citations：原文、文件、位置、版本、chunk_id、span_id、role。
- trace：四个执行节点及说明。

状态示意：

```json
{
  "evidence": [{"span_id":"<id>:s1","text":"<完整原文句子>","role":"direct"}],
  "open_questions": ["尚需模型或人工判断证据是否充分并支持答案"],
  "decision": "search"
}
```

证据由程序规则选择，不是模型生成；复用 Gate 是为了演示协议与来源检查。没有结果时允许 evidence=[] 且继续保留未解问题，Gate 可能仍为 true。

若 Chunk 命中但其可选句子全部超过 600 字符，也可能没有 citations。本原型并不自动截断或概括，以避免引入不满足 Gate 的伪摘录。

## 5. 页面到代码的逐步追踪

1. 页面按钮发送 `/ask`。
2. FastAPI 用 AskRequest 检查问题长度 2–2000。
3. OfflineRuntime.ask → graph.invoke。
4. retrieve 节点 → KnowledgeBase.search。
5. search 返回带 spans 的命中 Chunk。
6. build_evidence 挑选完整 span，生成严格三字段状态。
7. gate 重建 visible span 表，运行 parse_and_validate_state。
8. extract 根据已选 span 反查文件来源，生成 citations。
9. 页面用 textContent 展示，防止把原文当作 HTML 执行。

## 6. 常见误读

- `answer` 字段不代表经过大模型回答；以 mode 和内容为准。
- `decision=search` 不代表当前离线图会自动循环。
- `gate.ok=true` 不代表召回相关、不代表答案正确。
- Qdrant 使用 cosine 不代表输入一定是语义向量。
- SQLite / Qdrant 落盘不代表支持多进程、备份治理或审计。
- 客户端不传用户身份，因此当前接口无法安全实现企业用户级访问控制。
